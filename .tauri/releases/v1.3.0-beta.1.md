## Boris 1.3.0-beta.1

First beta of Boris 1.3 for Windows 10 and 11 x64. Stable installations stay
on 1.2.0 unless you select the Beta update channel. NSIS installer only.

### What's new

- Boris selects common tools for each task before the first model request.
  Research gets web and recall tools; workspace work gets file and shell tools.
  Discovery adds missing capabilities and keeps them across short follow-ups
  such as "continue" and "try again". A new objective clears those discoveries.
- Independent tool calls can run through an explicit `parallel` tool. The
  activity chip shows the batch and concurrency limit. Writes, confirmations,
  and typed input preserve ordering, without replaying completed work.
- A desktop developer monitor shows model requests, tool calls, routing,
  context, and provider usage. Capture can be exported, and individual events
  can be copied for debugging.

### Reliability

- Tool execution status stays separate from output text through parallel
  calls, confirmations, typed input, history, reminders, and model routing.
  Reading a log containing "error" no longer makes a successful call fail.
- Nonzero shell exits, missing search paths, and MCP tool errors report failure
  while keeping useful diagnostics. Timeout guidance asks for a safe retry or
  a narrower request.
- Namespaced `functions.` calls are normalized before dispatch and replay.
  Tool definitions, historical names, and arguments are checked before use.
- Failed report presentation keeps the complete body available on screen.
  When storage is writable, a recovery catalog preserves reports across restarts.
- Context updates preserve the conversation prefix. Incidental words and
  unclear dictated negation are no longer promoted into hard restrictions.
- Failed or cancelled turns and checkpoint restores recover the preceding
  discovered tools alongside conversation history.

### Install and update

1. Download `Boris_1.3.0-beta.1_x64-setup.exe` and run it over your existing Boris installation.
2. Select **Settings > General > Updates > Beta** to receive future beta updates.
3. On a first installation, finish model setup and add your OpenRouter API key in Settings.

Your `%USERPROFILE%\.boris` data stays outside the installation directory.
Upgrades from 1.2.0 retain the existing local memory store. Upgrades from
1.2.0-beta.1 or earlier retain the verified legacy-memory migration described
in the [1.2 release notes](https://github.com/blocksdevpro/boris-assistant/releases/tag/v1.2.0).

### Developer compatibility

- Skill names and descriptions already arrive in the prompt catalog.
  `list_skills` and `ListSkillsTool` are removed; use `load_skill` for a full body.
- Markdown-only memory exposes `memory_search_files` and `memory_get_file`.
  Deprecated aliases and their Rust types are removed. Canonical SQLite memory
  retains `memory_search` and `memory_get`. Enabling it removes fallback tools
  without deleting source files.
- Direct `AgentLoopConfig` and `ListToolsContext` struct literals need their new
  optional selection field or `..Default::default()`. `Agent::prompt` fills the
  selection automatically.
- Run `cargo run --offline -p boris-agent --example tool_selection_audit` to
  compare estimated schema tokens with scripted replies. The default research
  audit reduced first-request estimates from 4,299 to 1,533 tokens with the
  same three model requests. These estimates do not measure live latency.
